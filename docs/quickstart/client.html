Client setup

Operators reach machines through the gateway — never by SSHing straight to the agent (that bypasses recording and policy).

You can use:

  1. Web terminal in /ui (fastest after admin login)
  2. Vanilla OpenSSH (user+machine@gateway)
  3. osh / ocp / oadmin CLIs

Web console​

  1. Sign in at http://<gateway>:8080/ui with your Orion username + SSH public key (or password+TOTP / WebAuthn if configured)
  2. Open Terminal (or the machine’s connect action)
  3. Sessions appear under Sessions for playback / live watch

OpenSSH (no osh required)​

Username format: gatewayUser+machine or gatewayUser+remoteUser%machine.

ssh -i ~/.ssh/id_ed25519 -p 2222 alice+web-01@orion.example.com
ssh -p 2222 'alice+bob%web-01@orion.example.com'

One-shot:

ssh -p 2222 alice@orion.example.com 'bob@web-01 uptime'

Full details: main repo docs/openssh-clients.md.

osh CLI​

Build or install client packages from the main repo, then configure the gateway + key:

# example ~/.orion-belt/client.yaml
server:
  host: "orion.example.com"
  port: 2222
  api_endpoint: "https://orion.example.com/api"

auth:
  key_file: "~/.ssh/id_ed25519"
  username: "alice"

Typical usage:

osh web-01
osh --request-access web-01 --duration 1h --reason "Emergency deploy"

(ocp for SCP-style copy; oadmin for admin operations — see main repo CLI docs.)

Grants​

Before connecting, an admin must grant your user access to the machine (and which remote users are allowed), via Users / Permissions in the UI or:

orion-belt-server permission grant \
  --user alice --machine web-01 --type both --remote-users root

FAQ​

Auth failed — public key registered on the user? Correct private key locally? Agent online?

Permission denied / no machines — missing grant or wrong remote user.

Direct SSH to the host works but isn’t recorded — expected; point people at the gateway only.
