# Get started in 10 minutes

Install Orion Belt from the signed package repository at
[pkgs.orion-belt.dev](https://pkgs.orion-belt.dev), so it upgrades with the
rest of the system. Four steps:

| Step | Where | Time |
| --- | --- | --- |
| [1. Server](#1-server) | One Linux host that you and your machines can reach | 5 min |
| [2. Your computer](#2-your-computer) | macOS, Windows, Linux or BSD | 2 min |
| [3. Agent](#3-agent) | Each Linux machine you want to reach | 2 min |
| [4. Connect](#4-connect) | Your computer | 1 min |

The server needs ports **2222** (SSH) and **8080** (console and API) reachable
from your computer and your machines. The examples call it
`orion.example.com`; use its DNS name or IP address.

:::tip Only want to look around?
[Try it with Docker](./try-in-10-minutes) runs a server, a demo machine and a
recorded session on your laptop, with nothing to configure.
:::

## 1. Server

The server runs on Linux. On macOS or Windows, use the **Docker** tab.

### Install the server and PostgreSQL

<Tabs groupId="server-os" queryString>
<TabItem value="debian" label="Debian / Ubuntu" default>

```bash
sudo curl -fsSLo /usr/share/keyrings/orion-belt.gpg https://pkgs.orion-belt.dev/orion-belt.gpg
echo 'deb [signed-by=/usr/share/keyrings/orion-belt.gpg] https://pkgs.orion-belt.dev stable main' \
  | sudo tee /etc/apt/sources.list.d/orion-belt.list
sudo apt update
sudo apt install orion-belt postgresql
```

PostgreSQL starts on install. Also covers Raspberry Pi OS.

</TabItem>
<TabItem value="rhel" label="Fedora / RHEL">

```bash
sudo curl -fsSLo /etc/yum.repos.d/orion-belt.repo https://pkgs.orion-belt.dev/orion-belt.repo
sudo dnf install orion-belt postgresql-server
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql
```

Also covers Rocky Linux, AlmaLinux, CentOS Stream and Amazon Linux (use `yum`
where `dnf` is missing).

</TabItem>
<TabItem value="suse" label="openSUSE">

```bash
sudo zypper addrepo https://pkgs.orion-belt.dev/orion-belt.repo
sudo zypper install openssh-clients openssl postgresql-server
sudo zypper install orion-belt
sudo systemctl enable --now postgresql
```

zypper asks once whether to trust the repository key. Compare its fingerprint
with the one on [pkgs.orion-belt.dev](https://pkgs.orion-belt.dev), then answer
`a` (always). `openssh-clients` goes first because the package creates the
server's SSH host key with `ssh-keygen`.

</TabItem>
<TabItem value="alpine" label="Alpine">

```bash
sudo wget -O /etc/apk/keys/orion-belt.rsa.pub https://pkgs.orion-belt.dev/apk/orion-belt.rsa.pub
echo 'https://pkgs.orion-belt.dev/apk' | sudo tee -a /etc/apk/repositories
sudo apk update
sudo apk add orion-belt postgresql openssl
sudo chown -R orionbelt:orionbelt /etc/orion-belt /var/lib/orion-belt /var/log/orion-belt
sudo rc-service postgresql setup
sudo rc-service postgresql start
sudo rc-update add postgresql
```

The `chown` is needed on 1.4.0: apk leaves the server's directories owned by
root, and the server, which runs as `orionbelt`, could not read its config.

</TabItem>
<TabItem value="arch" label="Arch Linux">

```bash
curl -fsSL https://pkgs.orion-belt.dev/orion-belt.asc | sudo pacman-key --add -
sudo pacman-key --lsign-key F1E47F7B036D5202262E174F613B2217A8958DA9
printf '[orion-belt]\nServer = https://pkgs.orion-belt.dev/archlinux/$arch\n' \
  | sudo tee -a /etc/pacman.conf
sudo pacman -Sy orion-belt postgresql
sudo -u postgres initdb -D /var/lib/postgres/data
sudo systemctl enable --now postgresql
```

Check the key fingerprint against the one on [pkgs.orion-belt.dev](https://pkgs.orion-belt.dev).

</TabItem>
<TabItem value="docker" label="Docker">

On any OS with Docker and the Compose plugin. Nothing to clone: download the
compose file and write its settings.

```bash
mkdir orion-belt && cd orion-belt
curl -fsSLO https://raw.githubusercontent.com/orion-belt-dev/orion-belt/v1.4.0/docker-compose.prod.yml
ORION_HOST=orion.example.com    # the name or IP you and your machines use for this server
cat > .env.prod <<EOF
ORION_IMAGE_TAG=1.4.0
POSTGRES_PASSWORD=$(openssl rand -hex 16)
ORION_JWT_SECRET=$(openssl rand -hex 32)
ORION_PUBLIC_HOST=$ORION_HOST
ORION_PUBLIC_ORIGIN=http://$ORION_HOST:8080
EOF
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d
```

This starts the server and its own PostgreSQL. Create the first admin: the
wizard asks for a name, an email and your SSH public key (the line in
`~/.ssh/id_ed25519.pub` on your computer; create it with
`ssh-keygen -t ed25519` if you have none).

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod exec server \
  /app/orion-belt-server -c /etc/orion-belt/config.generated.yaml setup
```

Press Enter to keep the suggested SSH host and port. Then skip to
[step 2](#2-your-computer).

</TabItem>
</Tabs>

### Create the database

Skip this with Docker.

```bash
sudo -u postgres createuser orionbelt
sudo -u postgres createdb -O orionbelt orionbelt
```

The server connects over PostgreSQL's local socket as the `orionbelt` system
user the package created, so the database needs no password.

### Configure it

Set `ORION_HOST` to the server's name or IP, then run the whole block:

```bash
ORION_HOST=orion.example.com
sudo sed -i \
  -e 's|connection_string: .*|connection_string: "postgres://orionbelt@/orionbelt?host=/run/postgresql"|' \
  -e "s|change-me-to-a-long-random-secret|$(openssl rand -hex 32)|" \
  -e "s|https://orion.example.com|http://$ORION_HOST:8080|g" \
  -e "s|orion.example.com|$ORION_HOST|g" \
  /etc/orion-belt/server.yaml
```

This points `/etc/orion-belt/server.yaml` at the local database, sets a random
JWT secret, and sets the public address (`server.public_url` and the WebAuthn
`rp_id` and `origins`) to `http://$ORION_HOST:8080`. Once you put HTTPS in
front of port 8080 ([reverse proxy](https://github.com/orion-belt-dev/orion-belt/blob/master/docs/REVERSE_PROXY.md)),
change those values to `https://$ORION_HOST`. Security keys (WebAuthn) only
work over HTTPS.

### Create the first admin

You sign in as the admin with your SSH key. On your computer, print the
public half (create one with `ssh-keygen -t ed25519` if you have none):

```bash
cat ~/.ssh/id_ed25519.pub
```

On the server, run the setup wizard:

```bash
sudo -u orionbelt env ORION_SETUP_PUBLIC_URL="http://$ORION_HOST:8080" \
  orion-belt-server -c /etc/orion-belt/server.yaml setup
```

Press Enter to keep the suggested SSH host and port, then give an admin
username (`admin` below), an email, and paste the key line.

### Start it

The same command works with systemd, OpenRC, runit and SysV init:

```bash
sudo /usr/lib/orion-belt/orion-belt-server-service setup
curl -s http://127.0.0.1:8080/api/v1/version
```

The second command prints the version once the server is up. If a firewall
runs on the host, open ports 2222 and 8080.

Install `osh` (connect), `ocp` (copy files) and `oadmin` (administer):

## 3. Agent

The agent runs on each machine you want to reach and dials **out** to the
server on port 2222, so the machine needs no inbound port.

### Quickest: a generated install script

On your computer, generate a script for the machine (here `web-01`), copy it
over and run it:

```bash
oadmin agents install-script web-01 --gateway-host orion.example.com -o install-web-01.sh
scp install-web-01.sh web-01:
ssh -t web-01 'sudo bash install-web-01.sh && rm install-web-01.sh'
```

Generating the script registers the machine. The script works on any Linux
with `bash` (on Alpine, `apk add bash` first): it installs the agent and its
service, writes the config and key, and starts it. It contains the agent's
private key, so copy it only over a channel you trust, and delete it
afterwards. The console does the same under **Machines → Add agent**.

### Or: from the package

Use this when you want the agent to upgrade with the system's packages.

</TabItem>
<TabItem value="docker" label="Docker">

On the machine, with Docker and the Compose plugin:

```bash
mkdir orion-belt-agent && cd orion-belt-agent
curl -fsSLO https://raw.githubusercontent.com/orion-belt-dev/orion-belt/v1.4.0/docker-compose.prod.agent.yml
ssh-keygen -t ed25519 -f agent-key -N ""
cat > .env.agent <<'EOF'
ORION_IMAGE_TAG=1.4.0
ORION_SERVER_HOST=orion.example.com
ORION_AGENT_NAME=web-01
EOF
cat agent-key.pub
```

Register the key on the server as below, then start it with
`docker compose -f docker-compose.prod.agent.yml --env-file .env.agent up -d`.

</TabItem>
</Tabs>

Create the agent's key and point it at the server. Set the two names, then run
the block:

```bash
ORION_HOST=orion.example.com
AGENT_NAME=web-01
sudo ssh-keygen -t ed25519 -f /etc/orion-belt/agent_key -N ""
sudo sed -i \
  -e "s|^\([[:space:]]*host:\).*|\1 \"$ORION_HOST\"|" \
  -e "s|^\([[:space:]]*name:\).*|\1 \"$AGENT_NAME\"|" \
  /etc/orion-belt/agent.yaml
sudo cat /etc/orion-belt/agent_key.pub
```

Register that public key on the **server**:

```bash
sudo -u orionbelt orion-belt-server -c /etc/orion-belt/server.yaml \
  agent register --name web-01 --key "ssh-ed25519 AAAA… root@web-01"
```

With a Docker server, run it in the container instead:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod exec server \
  /app/orion-belt-server -c /etc/orion-belt/config.generated.yaml \
  agent register --name web-01 --key "ssh-ed25519 AAAA… root@web-01"
```

Back on the machine, start the agent (systemd, OpenRC, runit or SysV):

```bash
sudo /usr/lib/orion-belt/orion-belt-agent-service setup
```

## 4. Connect

From your computer:

```bash
osh --list                                 # web-01 shows as online
osh root@web-01                            # a recorded shell on web-01, as root
ocp ./notes.txt web-01:/tmp/notes.txt      # copy a file
```

`ocp` needs `scp` on the machine (`openssh-client` on Alpine; most other
distributions have it already). It does not work into the Docker agent image,
which has no `scp`.

Plain OpenSSH works too, without the tools:

```bash
ssh -p 2222 admin+web-01@orion.example.com
```

Admins can reach every machine. Everyone else needs a grant first, from
**Permissions** in the console or with `oadmin`:

```bash
oadmin permissions grant --user alice --machine web-01 --access-type both --remote-user root
```

Every session appears under **Sessions** in the console, where you can replay
it or watch it live.
