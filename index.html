Reach every server, desktop and cluster without opening a port.

Orion Belt is an access gateway you run yourself. Agents dial out to it, people ask for time-boxed access, and SSH sessions are recorded. SSH, RDP, VNC and Kubernetes, one audit trail.

What changes on day one​

Access tends to sprawl quietly: one more open port, one more key, one more shared credential. These are the defaults Orion Belt replaces.

Without itWith Orion Belt
A bastion with port 22 open to the internet, and every target reachable from it.Agents dial out to the gateway. Targets accept no inbound connections at all.
SSH keys copied to servers years ago, still valid for people who left.Access is a grant with an expiry. Short-lived SSH certificates if you turn on the CA.
A shared kubeconfig with cluster-admin in a team vault.A RoleBinding for one namespace, issued on approval and deleted when the grant ends.
RDP on 3389 behind a VPN, with no record of who connected.RDP and VNC through the same agents, each connection audited with who, when and how much.

From request to expiry​

  1. Ask

    Request time-boxed access from the terminal or the console, with a reason.

    osh root@web-01 -r --reason "INC-42" -d 1800

  2. Approve

    An admin approves in the console or Slack, or a risk policy approves low-risk requests on its own.

  3. Connect

    Your usual client, through the gateway. OpenSSH, RDP and VNC clients, and kubectl all work.

    osh root@web-01

  4. Expire

    When the window closes the grant is gone, and any Kubernetes binding with it. Nobody has to remember.

One gateway for every way in​

Every protocol uses the same agents, the same grants and the same approval. A grant for one protocol never opens another.

Answers for the people who sign off​

Who accessed what, and who approved it
SOC 2, ISO 27001 and PCI reports as CSV, PDF or JSON. Every session is tied to the request or grant that allowed it. Compliance reports
Why someone can, or can't, get in
osh explain root@web-01 walks the exact grants and roles the gateway checked. Denied sessions print the same answer.
Requests that look wrong
Each request records source, device, MFA and target sensitivity. A risk policy can send risky ones to an admin, and unusual sessions are flagged for review. Risk and anomalies
Strong sign-in
TOTP and WebAuthn for the console, FIDO security keys over SSH, and an optional SSH certificate authority for short-lived certificates.

Runs on your hardware​

No SaaS, no phone-home. Signed packages for Debian, Ubuntu, Fedora, RHEL, openSUSE, Alpine and Arch, and clients for macOS, Windows and the BSDs, all upgraded by your package manager. The guide takes you from install to a recorded session per system.

Questions people ask first​

Do targets need any inbound port open?

No. Each agent opens an outbound connection to the gateway and every session rides it. Only the gateway listens.

Can people keep their own SSH client?

Yes. ssh alice+web-01@gateway works with stock OpenSSH, as do Ansible and AWX. osh adds access requests, RDP, VNC and Kubernetes on top.

How does Kubernetes access end?

The gateway deletes the RoleBinding when the grant expires or is revoked, and checks every 30 seconds. The in-cluster agent also deletes expired bindings on its own, so access ends even if the gateway is down.

Are RDP and VNC sessions recorded?

Not yet. Each connection is audited, but the stream is encrypted end to end, so recording needs the gateway to terminate the protocol. That is on the roadmap.

What does it cost?

Nothing to self-host and use internally. It is Apache 2.0 with the Commons Clause: you may not sell Orion Belt itself as a product or hosted service.

What do I need to run it?

One Linux server with 2 cores and 4 GB of RAM, and PostgreSQL. Docker Compose for a lab, deb, rpm and apk packages for a real install.

Agents dial out. Sessions are recorded. Access expires on its own.​
