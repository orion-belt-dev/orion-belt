**Orion Belt 1.5.0** makes the gateway easier to automate and easier to
trust. It ships SDKs for every API endpoint, lets you manage agents from the
gateway, and fixes everything a security audit found. It is also the first
release under an open source license, and the first with build provenance
you can check.

{/* truncate */}

## Python and TypeScript SDKs

`pip install orion-belt-sdk` and `npm install @orion-belt/sdk` give you a
client for every `/api/v1` endpoint, with no runtime dependencies. CI checks
both against the server's route table, so a new endpoint can't ship without
them. See [SDKs](/docs/api/sdks) and
[the SDK post](/blog/orion-belt-sdks).

## Agent remote management

`oadmin agents reload`, `drain`, `undrain` and `update` run over the
connection the agent already holds open to the gateway. No SSH to the host,
no inbound port. Each command is admin or operator only and audited. See
[Agent remote management](/docs/guides/agent-management).

## Bulk grants and effective access

One call grants or revokes an access type for every user × machine pair, up
to 500, each applied and audited on its own. The console gains multi-select,
an effective access view and server-side search. See
[Permissions](/docs/guides/permissions-management#4-grant-or-revoke-many-at-once).

## Tunnels that survive network drops

Agents redial as soon as a link drops, with jittered backoff. The gateway
pings agents and clients every 15 seconds, so dead links are noticed quickly,
and a reconnecting agent is no longer shown as offline.

## Standard API errors

Every error now has a `code`: `invalid`, `unauthenticated`, `forbidden`,
`not_found`, `conflict`, `unavailable` or `internal`, each with a fixed HTTP
status. Internal details never reach a 500 response. See
[API errors](/docs/api#errors).

## Security audit fixes

An external audit in early November found four issues; all are fixed, along
with what we found while fixing them:

- Generated agent install scripts and `install-server.sh` verify every
  download against the signed `checksums.txt`.
- Deleting a machine keeps its recordings until the retention sweep. Agent
  registration, credential changes and file browser actions are audited. MFA
  backup codes can no longer be reused.
- The API server has timeouts, a request body limit and security headers.
- With a Host CA configured, agents no longer trust a gateway that omits its
  certificate.
- The server container runs as `orionbelt`, not root.

## Now AGPL v3.0

Orion Belt is now open source under the GNU AGPL v3.0, replacing Apache 2.0
with the Commons Clause. Using, modifying and running it stays free,
including commercially. [What changes and why](/blog/orion-belt-agpl).

## Verifiable releases

Every release file and container image comes with SLSA level 3 provenance
and a GitHub attestation, alongside the GPG signatures. You can check that a
binary was built by the release workflow from the `v1.5.0` tag. See
[Verify a release](/docs/quickstart/verify-release) and
[the post on how we build releases](/blog/verifiable-releases).

## Upgrade notes

- **JWT secret:** the server refuses to start with the example placeholder
  secret or one shorter than 32 bytes. Package installs and upgrades replace
  the placeholder with a random secret, which signs everyone out once. For
  Docker or hand-written configs, set one with `openssl rand -hex 32`.
- **Database migration:** the first start converts timestamp columns to
  `TIMESTAMPTZ`, rewriting each table once under a lock. Expect a pause on a
  large `audit_logs`. A non-UTC host whose time zone can't be detected needs
  `ORION_DB_LEGACY_TIMEZONE`.
- **Unsigned builds:** generated install scripts need signed release
  packages. For a local `dist/`, tick "Allow an unsigned local build".
- **Alpine:** the `chown` step from the 1.4.0 install guide is no longer
  needed; the package owns its directories correctly.
