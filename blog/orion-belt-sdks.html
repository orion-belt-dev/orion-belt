Automating Orion Belt from Python and TypeScript

November 18, 2026 · 3 min read
Orion Belt
Maintainers

Most of what people build around a PAM gateway is glue: a chat bot that files access requests, a nightly job that reviews standing grants, a deploy pipeline that asks for an hour on production. With 1.5.0, that glue can be written against a typed client in Python or TypeScript instead of hand-rolled HTTP calls.

pip install orion-belt-sdk        # Python 3.11+
npm install @orion-belt/sdk       # Node 20+, Deno, Bun, browsers

Complete by construction​

An SDK that covers "the main endpoints" quietly falls behind. These two cover every /api/v1 route, and they stay that way because the build says so.

The server's routes are generated from the Go router into sdk/routes.json. A server test fails if the router and the file disagree, and each SDK has a contract test that fails if a route has no method. Adding an endpoint without adding it to both clients turns CI red.

Both clients follow the Go SDK's method names (list_machines in Python, listMachines in TypeScript), so code ports between the three with little thought.

No dependencies​

The Python client uses only the standard library. The TypeScript client uses the platform fetch. Neither pulls anything into your dependency tree, which matters for a tool that holds admin credentials to your access gateway.

Log in with an SSH key​

Scripts don't need a stored password. Prove you hold a key registered to the user, and the client keeps the API key it gets back:

from cryptography.hazmat.primitives import serialization
from orion_belt_sdk import OrionBeltClient

key = serialization.load_ssh_private_key(open("id_ed25519", "rb").read(), password=None)


class Signer:
    public_key = key.public_key().public_bytes(
        serialization.Encoding.OpenSSH, serialization.PublicFormat.OpenSSH
    ).decode()

    def sign(self, data: bytes) -> tuple[str, bytes]:
        return "ssh-ed25519", key.sign(data)


client = OrionBeltClient("https://orion.example.com")
client.login_with_ssh_key("deploy-bot", Signer())

cryptography is only needed for this example; the SDK itself doesn't require it. Password and TOTP login, session tokens and JWTs work too. See SDKs.

Example: ask for an hour on a machine​

A deploy job that requests just-in-time access, then waits for a human to approve it:

import { OrionBeltClient } from '@orion-belt/sdk';

const client = new OrionBeltClient({
  baseUrl: 'https://orion.example.com',
  apiKey: process.env.ORION_API_KEY,
});

const machine = await client.getMachineByName('web-01');

const request = await client.createAccessRequest({
  machine_id: machine.id,
  reason: `deploy ${process.env.GIT_SHA}`,
  duration: 3600,
  remote_users: ['deploy'],
});

console.log(`Access request ${request.id} is waiting for approval`);

The approver sees the request, its reason and its risk signals in the console or in chat, and the access expires on its own an hour later.
