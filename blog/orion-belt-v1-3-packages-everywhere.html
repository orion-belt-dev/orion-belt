Orion Belt 1.3 — signed packages for every Linux distribution, clients for every OS

October 23, 2026 · 4 min read
Orion Belt
Maintainers

Orion Belt 1.3.0 (October 22, with 1.3.1 the next day) makes installing the gateway, the agent and the clients a package manager command on almost any machine. Everything comes from signed repositories at pkgs.orion-belt.dev, so upgrades arrive with the rest of your system updates.

Install in one line​

curl -fsSL https://pkgs.orion-belt.dev/install.sh | sh                # clients: osh, ocp, oadmin
curl -fsSL https://pkgs.orion-belt.dev/install.sh | sh -s -- agent    # agent (Linux)
curl -fsSL https://pkgs.orion-belt.dev/install.sh | sh -s -- server   # server (Linux)
irm https://pkgs.orion-belt.dev/install.ps1 | iex                     # clients on Windows

On Linux the script adds the repository for your package manager and installs from it. Every download is checked against the release's checksums.txt, and its GPG signature is checked when gpg is installed. If you'd rather not pipe to a shell, add the repository by hand; the Get started guide has the commands per OS.

Three packages per Linux platform: orion-belt (gateway), orion-belt-agent and orion-belt-tools (osh, ocp, oadmin). The server and agent packages work with systemd, OpenRC, runit and SysV init.

Why so many architectures​

Agents run where your machines are, and that's not only x86 servers: Raspberry Pis in a lab, ARM boards at the edge, s390x and ppc64le in older data centers. The agent is a single Go binary with no runtime dependencies, so building it for nine CPUs costs CI minutes, not maintenance.

Signed end to end​

  • The apt, dnf, zypper and pacman repositories are signed with the release GPG key.
  • .deb files carry an embedded signature and .rpm files a native one.
  • Every release file has a detached .sig, and checksums.txt is signed.

The key fingerprint is on the front page of pkgs.orion-belt.dev; compare it before you trust the repository.

Also in 1.3​

  • Capability catalog in the console (#57), building on the access catalog from 1.2.1: users see what they can request.
  • CLI coverage for the endpoints added since 1.0 (#64).
  • Gateway hardening: plugin settings validate admin-set URLs, paths and mail headers; Slack response_url posts are restricted; users can only delete their own SSH keys.
  • Exec fixes: one-shot commands (ssh user+web-01@gateway uptime) run on the machine named in the SSH username, no longer lose output, and no longer hang when the command fails. A shell's last output arrives before the session ends.

FAQ​

Is there an apt repository for Orion Belt? Yes: deb [signed-by=/usr/share/keyrings/orion-belt.gpg] https://pkgs.orion-belt.dev stable main, after downloading the key from https://pkgs.orion-belt.dev/orion-belt.gpg.

Does the agent run on a Raspberry Pi? Yes. The armhf build runs on Raspberry Pi OS, and arm64 on 64-bit Pi OS.

Can I run the gateway in Docker instead? Yes. Server and agent images are on GHCR for eight architectures.
